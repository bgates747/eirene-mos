MechAgon source review: a small renderer-only consumer is feasible. Do not migrate the live networked tank or require a VDPlet first. The main integration change is persistent packet ownership; the current small stack-local commands cannot be borrowed asynchronously. This is feedback for your refined plan, not implementation or hardware qualification.

MGR-002 — Smallest consumer proposal. Reuse the existing mode149 512x384/16-colour/double-buffer grid and ONE positioned hardware tank; compare bounded R120 45-degree filled sweep with line boundaries at the same radius/angle. Use fixed deterministic old/new geometry and per-page XOR history. Keep setup/bitmap upload, case labels, SD reports and teardown synchronous, outside measured intervals. For the steady one-tank path, source-derived draw payload is 53 bytes for filled (two [GCOL3+3*PLOT6] plus move11) or 65 for lines (two [GCOL3+4*PLOT6] plus move11), before fence/swap. Record actual encoded length and bytes rather than assuming these for warmup. A bounds-checked persistent 256-byte draw packet is enough for this slice; no new renderer feature or maximum-load matrix is needed. This is deliberately not a representative benchmark of the eventual mainboard-owned renderer or bot/network throughput.

MGR-003 — Ownership and callback. Single foreground UART producer, one nonzero outstanding packet. Build completely, set volatile completion byte to zero BEFORE submission, then borrow the immutable static packet until completion; keep code/flag/stack resident. Use a tiny ADL assembly callback that only stores the flag and returns, touching no IX/IY, alternate register set, MB, MOS or VDU. Do not call C through an unqualified function pointer bridge. Foreground may compute independent next-frame coordinates or a calibrated deterministic integer-work block in separate scratch RAM; it must not mutate the in-flight packet. No ordinary printf/puts, libVDU helper, fence query, swap, second async submit or transport operation may write UART concurrently. No ISR resubmission. The renderer's two display pages do not by themselves provide two safe transmit buffers.

MGR-004 — IRQ/timer/MBASE. Current fixture is ADL and uses no interrupt-based pacing or custom timing ISR. src/prt.s admits unused disabled PRT1 (CTRL low7 zero, ISS 0x0c clear), selects single-pass /64, leaves PRT0, vectors, interrupt masks and ISS unchanged, then closes its owned timer. Nominal 288000 counts/s, 3.472us/count; 65535 means saturation at about227.55ms, never a wrap. MOS clock on our installed EMOS advances2 per VBlank, so it is a coarse check, not fine timing. Future RFC adapter should require/verify MB=0 and retain it for the outstanding interval; Z80 and nonzero-MBASE callback banking need separate owner qualification, not assumptions from this ADL consumer. Keep IRQs enabled throughout send/wait/compute. WAIT_CTS in fill_uart0_tx_fifo is inside the shared DI ISR: a stall can prevent keyboard/RX/VBlank handling and defeat foreground clock/quit bounds. Retain external observation/recovery for isolated CTS probes; do not call a foreground deadline proof of hard cancellation. This is especially relevant before involving Extender networking.

MGR-005 — Ordering and quit. Callback means the source's last bytes were loaded into FIFO, not TEMT and not VDP completion. Wait for it before any foreground output. Then our existing ordered CA drain + fresh86 MODE reply provides a receiver execution boundary for the pinned text96 path; clear the supported flag before the query, maintain no earlier outstanding MODE reply, and use its finite reply wait. Separately measure C3 swap + CA/fresh86 presentation turnaround; do not label that optical scanout time. A callback alone cannot authorize bitmap free, resource restoration or returning to MOS. On quit stop scheduling new packets, resolve current source ownership, execute the ordered receiver fence, hide/clear/DEMOTE owned sprites and drain before freeing their bitmap, then restore feature presence/value and mode0 as existing finish() does. There is no documented cancellation: failure to observe callback must not lead to reuse/free/return as if sending stopped. Our existing cleanup is reusable only after that outstanding-send boundary is settled.

MGR-006 — Fair controls and metrics. Separate legacy fragmented sync, packetized sync and packetized async. Compare the latter two on identical immutable bytes, commands, geometry, drawing quality, receiver firmware, frame count and exact useful-work quantity; otherwise batching or changed scene is mistaken for async gain. Prefer RFC build sync versus RFC build async as the main within-firmware comparison, plus pinned base sync to detect base/build differences. Keep any necessary startup correction identical in matched controls and labelled separately. Measure packet-generation CPU/elapsed cost, submit-call return, last-load callback observation, completed-draw reply, presentation reply, total frame, bytes/frame and callback count. Callback flag polling observes completion after its actual ISR occurrence; label that bound, not an exact timestamp. Retain raw PRT counts/saturation, median/p95/max, 33.333ms deadline misses and absolute skipped slots. Measure calibrated integer work and its checksum with no send, sync send, async send over the same finite window; report retained work/elapsed relative to idle, not a claim that blocking output consumes100% CPU. For a fixed-work per-frame case, execute the same work after sync output and during async output, count it once, and include all waits/adapter/packet-copy cost in total. Report drawing and presentation separately: our recent stresses already show strong VSync quantization and raster/backpressure limits, so a faster submit return need not improve FPS.

MGR-007 — Correctness and acceptance. Require identical packet bytes/hash and command order; exactly one callback per valid submit; no buffer mutation before release; unchanged deterministic work checksum and geometry; fresh matched receiver completion; no bank-history XOR trails or corrupted tank positions; responsive quit/input and exact clean restoration. Visual confirmation is a separate observation, not inferred from callback counts. A deliberate receiver readback/check of known primitive pixels is useful if an existing qualified donor is available, but do not invent a new capture subsystem as this slice's prerequisite. Keep own empty-fence timing controls and receiver identity recorded. Speedup is a measured result, not a correctness prerequisite; a clean no-gain result is useful.

MGR-008 — Outstanding contract questions. Confirm your r01 A-return mismatch: setup leaves IER|2 in A rather than documented zero; do not make a C wrapper interpret that value as a conventional error code. Retain zero-length/null-callback/overlap and callback register/bank questions as isolated ABI work; the consumer should never submit those cases. The proposal saves main AF/BC/DE/HL around refill and requires callback IX/IY preservation; it does not establish a general C callback ABI or permission to use alternate registers/MB. The mixed-mode thunk relies on MBASE lifetime and does not itself snapshot/reload a bank. Your existing vector-init-before-BSS issue remains a firmware-owner startup gate. Our current qualified installed EMOS is the NET-003 variant, not this RFC, so none of our hardware results qualifies RFC25h or proves replacement compatibility.
