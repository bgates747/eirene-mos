2. **Direct-eZ80 seam exists, but a one-line async replacement is unsafe.** `/Agon/mystuff/AgonArcade/rally/include/road.hpp:10` defines a4096-byte `rally::Stream`. `Road::project` computes geometry; `Road::emit` at:185 resets and overwrites the stream. `/Agon/mystuff/AgonArcade/rally/src/main.cpp:304` currently sends that road buffer synchronously. It is global RAM and a good bounded source, but the next emit must not reuse it before source release. `drawScenery` runs before the road send; `drawTraffic` after it emits matrices and stock VDP helpers; player bitmap, HUD and swap follow. Sending only the road asynchronously while these continue through ordinary output risks byte interleaving/reordering and fails to test the intended batched application path.

3. **Concrete additional producers/lifetimes.** In main.cpp, `PollBackend::send`(:41) uses a stack four-byte GP query; `trafficMatrix`(:73) uses a local4096-byte Stream; `loadScenery`(:116) has another local command object; `text`(:158) passes caller strings, including reused stack `hud[41]`. Startup repeatedly rewrites `carUpload` for source/recolour blocks(:194–228) and emits library calls/mirror commands. Direct `vdp_*` and printf output also bypass the road Stream. These sources are safe only under their existing synchronous lifetime assumptions. Never borrow a helper's stack array or mutable upload block until after it returns. Serialize setup with no outstanding async transfer; before main-loop migration, route ALL per-frame output through one owned packet or explicitly wait source release before each remaining ordinary write. Guard the entire application's UART producer seam, not just one syscall callsite.

4. **Recommended minimum adapter, later implementation only.** One foreground producer, one outstanding immutable RAM packet, byte flag armed BEFORE syscall25h, and a flag-only assembly callback. Save caller-required IX/IY; preserve alternate registers if used, since the shown ISR branch saves only AF/BC/DE/HL. No callback MOS/VDU/stdio/file calls, allocations, packet construction, timer reconfiguration, queueing or resubmission. Use a verified ADL24 callback/RET with actual MBASE0 for the first case. Own C++ code does not explicitly change MBASE; that is not proof the entry environment always supplies0. Retain callback code/flag/data and source storage through completion. Begin with a static packet whose capacity is measured and overflow checked;4096 is the current ROAD-only capacity, not an established whole-frame maximum. A second RAM packet can hold the next prepared frame once ownership is explicit; it is not a second MOS submission or permission for an unbounded render queue.

5. **RFC contract questions are real dependencies.** In proposed `src/mos_api.asm::mos_api_uart0_async_send`, HL is passed through FIX_HLU24, then `uart0_async_send` publishes global pointer/count and builds its callback trampoline. In `src/serial.asm::uart0_async_send`, MBASE decides ADL versus SIS callback setup; the diff does not snapshot/change MBASE for the later ISR callback. Require an explicit stable-bank contract through final callback, actual upper BC bits, source-bank crossing and callback mixed-mode return. Do not infer caller mode solely from MBASE or borrow RC2's trampoline assumptions. Initial Rally case should avoid classic/Z80/bank switching. No overlap guard or queue is present: do not submit while pending. Zero length/null callback are excluded from normal game trials, with their exact behavior left to the API owner's isolated ABI review. Return documentation says A=0, but the shown service ends with A from IER|2, with no explicit zero; a C wrapper must not treat that as the promised success/error status until the outer ABI is resolved. No firmware fix is proposed here.

6. **Producer/interrupt/timer constraints.** Proposed `_uart0_handler` enters with DI and branches into `fill_uart0_tx_fifo`; each refill executes WAIT_CTS before OTIRX and finishes with EI/RETI. Therefore a CTS pause can hold the system inside an interrupt with other maskable interrupts disabled: UART RX/keyboard/VDP replies, VBlank, PRT and foreground input handling can all be delayed. An IRQ-based timeout does not independently bound that condition; an external finite observer/recovery plan belongs to the operator. Qualify bounded realistic CTS pauses and simultaneous RX before claiming responsive operation; no endless-stall soak is needed. Never invoke foreground submit/wait from a pacing/PRT/keyboard ISR. Never wait for callback with interrupts disabled. No source-lifetime critical section should cover transmission. The RFC's shared UART interrupt classification/priority must preserve RX packet handling under normal continuous output; source alone does not establish starvation/latency bounds.

7. **Rally timers and numerical work remain fixed.** Existing direct-eZ80 main uses interrupt-updated MOS time via double-read `rawClock`(:33) and no PRT ownership. Its elapsed-time loop can perform multiple motion/traffic ticks, while steering is applied once per frame. For the transport A/B, use deterministic fixed-step work or a trace so faster delivery does not silently change the number of physics operations, steering applications or packets. The derived TIM-002 guest PRT1 implementation is at `docs/tasks/RALLY-28/custom-vdp/timing-attribution/guest/baseline/src/timing_prt.asm`: nominal1kHz serviced24-bit counter; native.hpp:86 claims it and saves/restores interrupt vector0x0c. Setup/stop contains short DI sections; keep async idle around timer ownership transitions and never add UART work to that ISR. WAIT_CTS under DI may coalesce PRT/VBlank counts, so apparent reduced elapsed ticks can be lost serviced interrupts. Keep raw counters plus independent host/receiver observations; do not force clock ratios to match.

8. **Three completions, ordering and quit.** RFC callback occurs after final OTIRX FIFO load, before guaranteed wire TEMT and before VDP execution. Source may be reused after that callback; callback CODE/ISR unwind still needs normal lifetime. Source-release alone permits neither an optical completion claim nor arbitrary console-mode reset during queued receiver work. Final frame can contain its existing swap followed by a checked stock GP token (with CA flush before token if a drawing-drain boundary is required by the selected fixture). Keep exactly one outstanding receiver token and preserve command order. For library output after source release, require an owner-approved shared-UART serialization/TEMT recipe; do not assume synchronous RST18 coordinates with the RFC sender merely because the final source has been released. At exit: stop accepting new packets, await source release with interrupts enabled, establish required wire/receiver completion, then stop audio, unload native state if applicable, restore mode/cursor/callback/timer, save files and return MOS. Error/ESC must not return into MOS while an ISR still references application code/data. With no cancellation/finish API, a timeout is terminal uncertainty: keep code/data resident and use the authorized external operator recovery, not speculative detach/free/retry. Do not silently retrofit finish43h or invent cancellation.
