Do not equate checkout HEAD or old RC2 with installed behavior.

1. Integration boundary: proposed src/mos_api.asm:mos_api_uart0_async_send and src/serial.asm:uart0_async_send/fill_uart0_tx_fifo always select physical UART0. EMOS src/serial.asm ordinary VDU routing and emos_parallel route hooks, plus docs/architecture.md, require committed EMOS routing authority. Therefore first meaningful comparator is explicitly EMOS Legacy, eZ80 UART0 -> mainboard VDP, with P4 keyboard on independent EMOS-owned UART1. Do not expose this raw sender as supported ordinary VDU output in ExCom/ExExt or silently redirect only one comparator. Broader route-aware API integration is separate owner work, not this review. UART1/Port-C parallel work is not accelerated by this UART0 proposal.

2. Preserve existing EMOS receive protection: installed src/interrupts.asm:_uart0_handler saves IX/IY and alternate AF/BC/DE/HL around vdp_protocol; _vblank_handler also calls emos_keyboard_tick_entry. A merge must retain those branches and UART1 parser isolation rather than replace our handler wholesale with the RFC diff. RFC TX callback only has primary AF/BC/DE/HL saved; it must preserve IX/IY and alternate registers if used. Start with a tiny primary-register flag-only assembly callback, not a compiler-generated ISR/C call. Never call MOS, printf, VDU, SD or submit again from that callback.

3. Application owns source buffer, completion flag, foreground work, sequencing, timeout/reporting and quit state. Arm done=0 BEFORE submit; submit only one nonzero immutable contiguous ADL buffer; do not overwrite/free it or leave its bank before callback. No implicit queue or overlap. Keep interrupts enabled during foreground waits/work. Do not put submission in pacing ISR or hold DI across wait. RFC final callback runs after FIFO load, before physical UART drain and before VDP execution. Source-release timing, physical TEMT drain and an existing receiver fence are three distinct observations. No ordinary VDU/header/query output or route switch until the admitted stream is serialized and the selected receiver fence completes. Final quit must finish that sequence before freeing callback/code or returning to MOS. A timeout is a failed stop requiring evidence/recovery, not permission to return with a live callback.

4. WAIT_CTS spins under DI in fill_uart0_tx_fifo. A P4 keyboard UART1 IRQ, vblank clock/pacing and UART0 replies can all be delayed even though their wires are separate; the MOS clock is not an independent bound during that stall. Qualify short finite CTS pauses with an external observer, preserve RX/input evidence and report maximum response delay. No prolonged stuck-CTS destructive probe is needed for an initial useful benchmark. A claim of nonblocking submission does not establish bounded interrupt latency.

5. Callback/bank questions are release blockers for a generic SDK, but not for a deliberately ADL-only first fixture. FIX_HLU24 fixes source only; MBASE chooses callback encoding. Need explicit permitted MBASE, BC upper-byte, bank lifetime, callback return-mode and register contract. Do not assume ADL application implies MBASE zero. Return A=0 disagrees with actual IER value; adapter must not interpret it as success. Zero length/null callback/overlap remain outside valid workload pending contract decisions. Startup vector-before-BSS defect must be resolved for any runnable binary and matched controls; retain exact proposal versus corrected variant labels.

6. Minimum useful suite: reuse the existing uart0-performance2 assembly work counter and receiver correctness method. (a) Valid 1/15/16/17 and 255/256/257 spans plus one 1024-byte span, one producer/flag callback, observed exact bytes and one completion. (b) Identical bounded render packet or existing receiver buffer upload, identical receiver and packet bytes, repeated finite windows with sync output versus RFC25. (c) Separate useful-work counter during continuous sending and at fixed 44100 payload B/s in 256-byte packets. No need to invent a new framework, CRC or resident diagnostic service. Retain actual expected/received byte comparisons as host-side evidence; do not add checksums to EMOS/VDP traffic.

7. Metrics table should show matched sync/RFC25 side by side: payload and wire B/s, submit time, callback source-release time, final drain/fence time, useful-work iterations/s and retained fraction versus idle, input response/missed pacing slots, exact byte/order/completion failures. Keep receiver rendering and sender work separate. Report median/tail across repeated windows and worst-case input delay. MOS clock nominal +2/vblank means 120 units/s at 60Hz but only 60 distinct updates/s; do not call it centiseconds or use it for tiny operations. Our no-IRQ unused-PRT1 /64 donor can time short slices (nominal 288000 counts/s at18.432MHz, saturation~227.55ms), only after runtime ownership/source checks, no IRQ/vector changes; do not allocate PRT0. No hardware calibration is implied.

8. Code-size review: do NOT estimate flash from diff lines or promise fit from older free-space reports. Compare actual linked ROM end/map and RAM BSS on the identical compiler/config baseline, then separately measure merged EMOS. RFC declares 11 BSS bytes (two three-byte counters/pointers plus five-byte callback thunk), in addition to text/ISR cost. Keep reusable packet construction, double buffering, polling, callback flags and metrics in app space; no resident benchmark hooks/queues/formatting justified. Do not introduce an extra MOS service merely to make the suite convenient.

9. Appliance feasibility: existing Pi Python staging/EXEC/GET and mode lifecycle can drive a finite explicit CLI appliance after separate source/firmware review and actual physical lease. Preserve autoexec, conditionally select mode with >=1s monitor settle, restore entry mode and visible flashing-cursor CLI, collect durable result before handback. Mainboard keyboard unavailable; current admitted P4 input must remain functional. Reset must boot normally, never restart test. No hardware reservation is requested here; MechAgon is current sole operator under retained generation39. Emulators qualify contracts/correctness, not actual throughput. Firmware owner retains reproducible exact binary/rollback; do not reintroduce routine full-flash backups per run.

Conclusion: agree with a small valid ADL/Legacy benchmark first, retaining application ownership of almost all logic. Raw route bypass, ISR/CTS coexistence, callback lifetime/context, startup ordering and actual linked-size accounting need explicit dispositions before claiming generic EMOS compatibility. This review grants no implementation or run authority.
